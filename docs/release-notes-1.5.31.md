# 1.5.31

**修玩家反馈的误触发：背包里悬停物品按 Alt，弹出的是「日志第 N 个任务」**

感谢这位玩家的反馈，两条根因都排查得很准，全部修了。

## 根因 1：`QuestLogShown()` 被整合包的微型菜单骗了

EllesmereUI 这类整合包会在常驻菜单栏放一个 `EUI_MicroMenu_QuestLog` 微型按钮（宽 158）。
它名字带 `QuestLog`、宽度也够，于是被当成「任务日志的根帧」——
插件从此认为**任务日志永远开着**，所有依赖这个判断的逻辑全跟着错。

现在日志根只收**面板级帧**：
- `GetObjectType() == "Button"` 的一律不算（微型按钮、行按钮都是 Button）
- 名字带 `Micro`（微型菜单）的也排掉

## 根因 2：兜底拿背包格子的 ID 当任务日志索引

兜底逻辑是「日志开着 + 提示框显示着 + 鼠标下是个带数字 ID 的按钮 → 那就是日志第 N 行」。
但**背包格子的 `GetID()` 就是槽位号**（1, 2, 3…），正好能换出日志第 1、2、3 个任务 ——
所以同一个物品放第 1 格弹第 1 个任务、放第 2 格弹第 2 个。

现在新增 `IsInBagOrBar()`：只要帧的祖先链里有下面这些容器，就不参与任务识别
（兜底扫描和鼠标矩形扫描两条路都排掉了）：

`Container` / `Bag` / `ActionButton` / `MultiBar` / `MicroMenu` / `MerchantFrame` /
`Auction` / `BankFrame` / `MailFrame` / `TradeFrame` / `CharacterFrame` / `SpellBook`

## 顺手把玩家提到的体验做成正式功能

> 「这个'对着背包任务物品按 Alt 查任务线'的体验其实非常惊艳，如果能正式做成
> 通过 C_Container 检测背包任务物品并弹窗的正式功能就太棒了」

已经做了，走的是 QuestieDB 物品表的 `startQuest` 字段（比 `C_Container` 更直接，也不依赖容器 API）：

- 鼠标停在**任务起始物品**上，按 Alt（任务日志快捷键）→ 弹出这件物品开启的整条任务链
- 背包、银行、邮件里的物品都行
- 不是任务起始物品（比如任务奖励物品）→ 什么都不做，不会乱弹
- 查不到 QuestieDB 物品表时同样静默

## 回归测试

新增 `tests/run_test_bag_false_positive.lua`：

- 微型菜单按钮不算日志帧、不进日志根列表
- 背包第 1 格 / 第 2 格按 Alt 都不弹窗（以前分别弹日志第 1、第 2 个任务）
- 任务起始物品按 Alt 弹出它开启的那个任务（4001，而不是日志里的 3001）
- 普通物品按 Alt 不弹
- 任务日志行按 Alt 照旧正常（不能被这次改动误伤）

顺带把本地校验脚本收进仓库了：`tests/check.py`（语法检查 + 跑全部 17 个测试文件）。

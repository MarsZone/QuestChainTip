# 1.5.18

## 修好了：任务日志里按 Alt 还是不弹窗

问题出在钩子的时机上。任务日志的标题按钮（`QuestLogTitle1..N`）是**打开任务日志时才创建**的，
而插件的钩子是在登录时装的 —— 那一刻这些按钮一个都不存在，所以一个也没挂上。
`/qct qlog` 里那句「任务日志按钮数: 0 / 全局处理器: 不存在」就是证据，
于是 `questLogButton` 永远是 nil，按 Alt 什么也不会发生。

现在改成**按键那一刻现场问鼠标**：`GetMouseFocus()` 拿鼠标压在哪个按钮上，
用它的 `GetID()` 去查任务日志索引。三条路依次尝试，前一条走不通就走下一条：

1. 鼠标焦点帧（含祖先）的 `GetID()` → 任务日志索引
2. 任务日志帧里逐行问 `IsMouseOver()`
3. 提示框第一行标题反查任务日志

完全不依赖任何钩子，也不依赖客户端给按钮起什么名字。同时钩子也改成在
`QUEST_LOG_UPDATE` 和任务日志 `OnShow` 时补挂，不再只挂一次。

顺带把误伤挡住：动作条按钮也有 `GetID()`，拿它的 ID 去查日志索引会开出完全无关的任务，
所以只认任务日志里的帧。

## 修好了：装了自绘 UI 时血量数字不显示

上一版直接拿 `_G.TargetFrame`，再在里面递归找第一个 `StatusBar`。在装了 pfUI 这类
自绘 UI 的客户端上，这个做法全线失效：

- 暴雪的 `TargetFrame` 还在，但整条父链被隐藏了 —— 文字挂上去，屏幕上什么也看不见；
- 自绘框体的血条可能不是 `StatusBar`（Frame + 贴图做的），递归找不到；
- 血条找到了，但和法力条长得一样，挑错就把数字叠到蓝条上。

现在改成：

- **先收集候选框体**：暴雪默认框体 → `pfUI.uf[unit]` → 扫 `UIParent` 找 `unit` 字段对得上的；
- **只挑当前真的可见的**（连祖先一起看，被隐藏的暴雪框体不算）；
- **血条按名字优先（Health / hp），其次按面积最大**，不再随便拿第一个；
- 实在找不到血条，就在框体上盖一层独立 Frame 放文字（至少能看见）；
- 目标/焦点变了、或者 UI 包刚建好自绘框体，会自动重新挑一次（限流 1.5 秒）。

## `/qct health` 现在真的能诊断了

上一版的诊断自己先炸了：里面 `tostring()` 了可能是 secret value 的返回值，
函数在第一个单位那里就中断，聊天框里只剩「---- 血量诊断 ----」和「开关: true」两行，
等于没诊断。现在每个值都兜一层 `pcall`，并且会打出：

- 单位是否存在、当前/最大血量；
- 文字内容、是否可见、挂在哪；
- **候选框体一览**（每个框体是显示还是隐藏、有没有找到血条）；
- 最终选用了哪个框体、哪个血条。

装了自绘 UI 的玩家跑一次 `/qct health`，就能看出该往哪儿挂。

## `/qct qlog` 也升级了

现在会显示：任务日志是否开着、鼠标焦点帧叫什么、它的 ID、
以及「鼠标下能定位到的任务」和定位来源。旧钩子的状态保留在最后一行，方便对照。

# 1.5.20

你的两张截图把两个问题都钉死了。

## 一、血量数字跑到「你不看的那个框体」上了

截图里两个目标框体同时存在：

- **左上角**（名字在上、红条、右边金色边框的「21」）—— 你实际在看的，UI 包的框体
- **右下角**（绿色血条写着 `691 / 691`、右边有鳄鱼头像和等级圈）—— 暴雪默认的 `TargetFrame`

数字出现在右下角，说明插件把文字挂到了暴雪默认框体上。

原因是候选框体的优先级：之前把 `_G.TargetFrame` 排在第一位，装了自绘 UI 时它往往还留着、
甚至还在显示，于是永远先命中它。

现在改成：

- **自绘 UI 的框体排在暴雪默认框体前面**（`pfUI.uf[unit]` → 扫 `UIParent` 找 `unit` 字段对得上的 → 最后才是 `_G.TargetFrame`）；
- 扫描时加了尺寸筛选（宽 ≥ 40、高 ≥ 15），避免挂到 0 尺寸的辅助帧上；
- **第一次成功显示时会在聊天框说一句**：`血量文字已挂到: xxx | 所属框体: yyy`。
  万一还是挂错了，把这一行发我就行；
- 新增 `/qct health <帧名>` 手动指定，`/qct health reset` 恢复自动；
- `/qct health` 的候选框体一览加了**屏幕坐标**，一眼就能分清哪个是哪个。

## 二、任务日志按 Alt 没反应 —— 根因是客户端没有 GetMouseFocus

`/qct mouse` 的输出说得很清楚：

```
这个客户端没有 GetMouseFocus
任务日志开着: 否 | 日志帧: 无
```

1.5.18 / 1.5.19 那套「按键那一刻问鼠标压在哪」的定位，**完全建立在这个不存在的 API 上**，
所以按多少次都不会有反应。

现在的方案不依赖它：

- 任务日志的每一行按钮在 **OnEnter 时自己记下「我是第几条、对应哪个任务」**；
- 按 Alt 时用**按钮自己的 `IsMouseOver()`** 判断鼠标是否还停在那行上（这个方法不需要任何全局函数）；
- 钩子在 `QUEST_LOG_UPDATE` 和日志 `OnShow` 时补挂 —— 因为行按钮是打开日志时才创建的，
  登录时挂等于挂空（这也是之前「按钮数: 0」的原因）；
- 名字对不上时，直接扫任务日志帧里的子按钮按结构挂（自绘任务日志也能覆盖）。

## 顺便让「按了没反应」自己说话

```
按 Alt 没找到任务行 | 任务日志开着: 是 | 日志帧: 有 | QuestLogTitle1: 有 | 已挂钩子行数: 24

```

如果还不行，把这两行发我，就能直接定位到是哪一环断的。

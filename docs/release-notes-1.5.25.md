# 1.5.25

**修：按 Alt 弹出来的是「上次 Shift 看的那个任务」**

## 为什么会这样

按 Alt 的那一刻，插件先现场扫鼠标下压着什么。扫不到的时候，老代码会往后退一步，
用缓存里的任务 ID 兜底 —— 而那份缓存是**上一次 Shift 悬停**留下的。

所以真实的操作顺序是：

1. 你在别处（世界地图的任务列表 / 地图图标）按 Shift 看过任务 A，插件记住了 A
2. 你打开任务日志，鼠标停在任务 B 上，按 Alt
3. 现场没扫到 B → 退回缓存 → 弹出的是 **A**

表现出来就是「Alt 弹的是上次 Shift 选的那个」。

## 这一版怎么改的

- **Alt 只认「按键这一刻现场查到的任务」**。现场扫不到就清掉缓存、播报现场，
  绝不再拿缓存开窗
- `TryOpenFromHover` 里「任务日志行」那条分支也加了同样的拦截：
  缓存里的 ID 一律作废，重新现场查一次
- 如果鼠标下确实识别不到行，只能退回「任务日志里选中的那条」，
  聊天框会明说一句：
  `用的是任务日志里选中的那条：#1234（鼠标下没识别到行；点一下目标行再按 Alt）`
  —— 不再让人误以为还是 Shift 的残留
- 顺带：有的客户端把**任务 ID 本身**塞进按钮的 `GetID()`（而不是日志索引），
  现在也认（超过 200 的数字按任务 ID 处理，日志索引不会那么多条）

## 回归测试

新增一条用例，先把「Shift 看过 3005」的缓存摆好，再在空白处按 Alt：

- 修复前：弹出 3005（就是玩家遇到的现象）
- 修复后：不弹窗，缓存被清掉；接着把鼠标放到真正的行上按 Alt，弹的是这一行（3001）

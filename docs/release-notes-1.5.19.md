# 1.5.19

这一版是拿你的报错截图直接定位的，之前三轮的方向全错了，先说清楚错在哪。

## 你截图里那行报错才是真凶

```
Core.lua:91: invalid value (secret) at index 5 in table for 'concat'
```

index 5 对应的是「血量」那个值。也就是说 **`UnitHealth` 返回的是一个 secret value**，
而且这个客户端对它调用 `tostring()` **不报错**，只是把 secret 原样返回 ——
真正抛错的是后面的字符串拼接。

所以：

- 我之前的 `pcall(tostring, x)` 兜底完全没用（tostring 本来就没抛）；
- 血量显示从 1.5.15 起就没成功过一次，因为 `string.format("%d / %d", cur, max)`
  那行自己就抛错了，文字根本没被设置过。前三版修的「层级不对」「框体找不到」全是无用功；
- 诊断本身也在第一个单位那里中断，所以 `/qct health` 只剩两行。

## 修好了：血量数值现在能显示

既然不能把血量读出来加工，那就**不加工**：

- 文字拆成三段独立对象：「当前值」「/」「最大值」；
- 当前值和最大值各自把**原始值**直接交给 `FontString:SetText`
  （secret value 不允许读，但允许这样「显示」）；
- 中间的 `/` 是静态文字，不需要读血量。

如果连 `SetText` 都被拒绝，会自动把文字藏起来并只记一条日志，不会刷屏。
`/qct health` 里新增了一行 **「能格式化成字符串: true/false」**，
以后一眼就能看出卡在「读」还是「显示」哪一步。

## 修好了：所有诊断不再自己崩

`QCT:Print` / `Debug` / `Trace` 统一走新的消毒函数：先 `tostring`，
再用**拼一次**当探针，拼不动就替换成 `<secret>`。整个插件的诊断输出都受益。

## 任务日志 Alt：现在会自己播报现场

你说「按 Alt 还是没反应」——我没法在你机器上看，所以让它自己说：

**按 Alt 没开出窗时，聊天框会自动打一行**，内容是那一刻的真实状态：

- 鼠标焦点帧叫什么、它的 ID；
- 任务日志是否开着；
- 提示框是显示还是隐藏、持有者是谁；
- 鼠标焦点帧的完整祖先链。

只在「任务日志开着」或「鼠标确实压在任务日志行上」时才说话，3 秒内最多一条，
拿 Alt 做别的事不会被刷屏。**下次按完 Alt，把那一行发给我就够了**，不用再输命令。

另外新增 `/qct mouse`，随时可以看鼠标现在压在哪个帧上（类型 / ID / 祖先链 / 提示框持有者）。
